# Deploying SoftMyMarket on aeonfree (softmymarket.hstn.me)

Everything in this document is specific to the free aeonfree plan used for the
first deployment. The generic guide is [DEPLOYMENT.md](DEPLOYMENT.md).

| Item | Value |
| --- | --- |
| Domain | `http://softmymarket.hstn.me` (enable SSL → `https://`) |
| MySQL host | `sql306.hstn.me` |
| Database | `mseet_43261025_softmymarket` |
| DB user | `mseet_43261025` |
| Table prefix | *(empty)* |
| Admin login | `admin@softmymarket.hstn.me` / `SoftMy@Admin2026` → **change on first login** |
| PHP needed | 8.1+ (8.2/8.3 recommended) |

---

## 1. Upload the project

1. Download this repository, then upload **all folders and files** to the
   account's web root (`htdocs/` on aeonfree — the folder that serves
   `softmymarket.hstn.me`).
2. Keep the structure: `admin/`, `includes/`, `database/`, `storage/`,
   `assets/`, `config/` must sit next to `index.php`.
3. **`config/config.php` is not in the repository** (it holds the database
   password, and the repo is public). It exists in the project workspace — upload
   it too, or create it from `config/config.example.php` and paste the values
   below.

```
db.host = sql306.hstn.me
db.port = 3306
db.name = mseet_43261025_softmymarket
db.user = mseet_43261025
db.pass = <the database password>
app.key = <64 random hex characters, generated by the installer or
           php -r "echo bin2hex(random_bytes(32));">
app.url = ''            ← leave empty; links follow the scheme the visitor uses
session.secure = true   ← already relaxed automatically when the site is on http
```

> **Rotate that database password.** It was shared in plain text during setup.
> aeonfree → MySQL Databases → change password, then update
> `config/config.php`. Nothing else depends on it.

## 2. Import the database

The project ships two SQL files. Both are plain MySQL 5.7 / MariaDB compatible —
no `DEFINER`, no routines, no `SUPER` privileges.

| File | What it does |
| --- | --- |
| `database/install.sql` | 23 tables + indexes + foreign keys + default settings + the first administrator |
| `database/demo-data.sql` | *(optional)* 12 categories, 8 brands, 12 products, 5 coupons |

**phpMyAdmin → select `mseet_43261025_softmymarket` → Import → choose
`database/install.sql` → Import.** Then repeat for `database/demo-data.sql` if
you want a populated storefront.

Notes

* `install.sql` starts with `DROP TABLE IF EXISTS` for every table, so it is
  safe to re-run; it never touches other databases.
* `SET NAMES utf8mb4` and `SET time_zone = '+05:30'` are inside the file, so do
  not change the phpMyAdmin defaults.
* No `CREATE DATABASE` / `USE` statements are included — the free plan only lets
  you import into a database you already own. Pick it in phpMyAdmin first.
* The last `SELECT` in each file prints a summary (`tables_created`, row counts)
  so you can confirm the import succeeded.
* If phpMyAdmin rejects the upload size, import from the SQL tab with
  "Import from URL" disabled, or split at the comments — the file is only 31 KB.

Verify from the dashboard afterwards: **Admin → Tools** shows the table row
counts, PHP extensions, writable folders and MySQL version.

## 3. First run checklist

1. Open `http://softmymarket.hstn.me/` — the storefront loads with the demo
   products (or an empty state if you skipped `demo-data.sql`).
2. Sign in at `/login.php` with `admin@softmymarket.hstn.me` / `SoftMy@Admin2026`.
3. **Change the password**: Admin → My account.
4. **Admin → Tools → "Lock the installer"** — writes `storage/installed.lock`.
   (`install/` is also blocked by `.htaccess` on this plan.)
5. **Admin → Settings** — store name, support email/phone, shipping fee, tax,
   bank-transfer accounts, gateway credentials.
6. **Admin → Tools → "Seed demo data"** — safe web seeder for the free plan
   (no SSH): 120 products / 50 customers per run, repeat a few times, or upload
   the SQL import of a locally generated dump.

### 3a. If something does go wrong

Three things are guaranteed so a problem never turns into a mystery:

| What you see | What it means | What to do |
| --- | --- | --- |
| **"One setting is missing: app.key"** page | `config/config.php` still has the placeholder secret. Password-reset and tracking links are signed with it, so it must be random. | Run `php -r "echo bin2hex(random_bytes(32));"` (or any 64-character hex generator) and paste it into `'key' => '...'`. |
| **"We hit a snag"** page with a reference like `SMM-20261025-090435-FB513D` | A bug we have not caught yet. The page never leaks a stack trace to visitors. | Open `storage/logs/error-YYYY-MM-DD.log` — the first line for that reference holds the exception, the file, the line and the trace. Send that line with the reference. |
| **`storage/logs/php-error.log`** | Raw PHP warnings — notices, deprecations, failed uploads. | Check it after deploying; the storefront keeps running through deprecations and warnings on purpose. |

Notices, warnings and deprecations are logged and swallowed (never converted into
fatal errors), because free hosts frequently ship a newer PHP than the code was
written for. Only real failures reach the error page.

## 4. Care and feeding on a free plan

**No SSH?** Everything that needs the CLI has a dashboard equivalent:

| CLI | Dashboard |
| --- | --- |
| `php tools/seed.php --products=10000 --customers=10000` | Admin → Tools → Seed demo data (batched) |
| `php tools/deploy-check.php` | Admin → Tools (runtime + row counts) |
| `php tests/run.php` | *(CLI only — safe to skip on the host)* |

**Execution limit** — free hosting usually caps PHP at 30 s per request. The web
seeder caps each run at 2 000 products/2 000 customers and defaults to 120/50 —
press "Generate" repeatedly to grow the catalogue.

**Storage quota** — the Google-Drive image proxy caches images under
`storage/cache/images/`. Every product picture viewed once is stored locally.
Delete that folder from the file manager if you approach the quota; the proxy
re-creates entries on demand.

**Email** — `mail()` is used by default (`mail.transport = 'mail'`). If order
confirmation emails do not arrive, either configure SMTP credentials in
`config/config.php` (`transport => 'smtp'`), or set `transport => 'log'` so mail
is written to `storage/logs/mail.log` instead of erroring.

**HTTPS** — aeonfree issues a free certificate. Once `https://softmymarket.hstn.me`
loads without a warning:

1. uncomment the HTTPS redirect block in `.htaccess`;
2. uncomment the `Strict-Transport-Security` header;
3. set `app.url = 'https://softmymarket.hstn.me'` in `config/config.php`.

**If every page returns 500** — the host most likely rejected one directive in
`.htaccess`. Comment out the `Options -Indexes` line first (that is the usual
culprit on free plans), then the `<IfModule mod_php.c>` block.

**If the site redirects to `/install/`** — `config/config.php` is missing.
Upload it; the installer is intentionally blocked by `.htaccess` on this plan.

---

## 5. Backups

Free plans rarely include automated backups.

* **Database:** phpMyAdmin → Export → *Quick*, format SQL → save the `.sql` file
  somewhere safe (weekly, and always before importing anything).
* **Files:** download `storage/` (uploads + `config/config.php` lives one level
  up) at the same time.
* Keep `app.key` — losing it invalidates password-reset and tracking links.

---

## 6. When you move to paid hosting

1. Export the database, import it on the new host.
2. Copy the files; keep `config/config.php`, `storage/uploads/`,
   `storage/cache/`.
3. Update `db.*` and `app.url` in `config/config.php`.
4. Run `php tools/deploy-check.php` on the new server.
5. Keep the domain: point `softmymarket.hstn.me` → your own domain in
   `app.url` and in the gateway callback URLs
   (`/payment/notify.php?gateway=…`, `/payment/return.php?gateway=…`).

## Third-party scanners, `?i=1` and "We hit a snag"

Two things on a free aeonfree account can make an automated audit look worse
than the site really is:

**1. The `?i=1` browser check.** Free hosting answers the first request from a
new visitor with a small JavaScript challenge and then redirects to
`https://softmymarket.hstn.me/?i=1`. A real browser runs the script and sees the
store. Scanners that only download HTML (the static part of most "website health
check" tools) see the challenge page instead — which has no `<title>`, no
viewport tag, no navigation and no footer, so they report exactly those items as
missing while their Lighthouse run (which executes JavaScript) scores the real
page at 99/100.

If a report shows *title / meta description / viewport / navigation / footer*
missing, open the URL it scanned in a private window: if it lands on `/?i=1`
first, the scanner never reached the app. Re-check with a tool that follows the
challenge, or after the host disables the check (some accounts can turn the
security system off once a custom domain or SSL is added).

**2. "We hit a snag" (HTTP 500).** That is this app's own error page, not the
host's. It always prints a reference id, e.g. `SMM-20261025-084322-1a2b3c`:

* the matching stack trace is in `storage/logs/error-YYYY-MM-DD.log`
* `php tools/deploy-check.php` prints the newest lines and flags missing files
* the usual causes on this host are a partial upload (a new file such as
  `includes/maintenance.php` not being copied, or a file uploaded with 0 bytes)
  and a stale `storage/` folder that is not writable (chmod `755`, or `775` if
  the host runs PHP under a different user)

Uploads are safest as a **zip extracted on the server** so no file is skipped.
